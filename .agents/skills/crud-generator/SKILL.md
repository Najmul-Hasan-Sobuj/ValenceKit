# ValenceKit admin CRUD

Use this skill when creating or extending an admin CRUD module. First read `AGENTS.md`, applicable `.ai/rules` if present, and the relevant domain skills. Check installed package versions and Laravel Boost documentation as instructed there. Inspect the closest current module and shared components before implementing: these files, rather than a frozen template, are the source of truth.

## Choose a comparable module

- `resources/js/pages/admin/categories/Index.vue`, `CategoryDrawer.vue` and `app/Http/Controllers/Admin/CategoryController.php`: resource-backed, paginated CRUD with a create/edit drawer, filters, status switches and delete confirmation.
- `resources/js/pages/admin/authorization/Users.vue` and `UserDrawer.vue`: admin invitation/edit drawer, permission-sensitive actions and system-account safeguards.
- `resources/js/pages/admin/authorization/Roles.vue`, `RoleCreate.vue`, `RoleEdit.vue`, `RolePermissions.vue`: role list with separate create/edit pages for complex permission forms. The list currently filters and paginates locally; do not copy that choice for unbounded datasets.
- `resources/js/pages/admin/finance/Index.vue`, `TransactionDrawer.vue`: transaction filters, pagination, drawer and single/bulk delete confirmations. `resources/js/components/SidebarFinanceTracker.vue` implements the sidebar overview.
- `resources/js/pages/admin/Dashboard.vue`, `McpUsage.vue`, `AuditLogs.vue`: dashboard cards and reporting lists; these are not generic CRUD templates. Settings pages use `AdminSettingsLayout.vue`; inspect the relevant page under `resources/js/pages/admin/settings/` for settings-specific forms.

## UI consistency

- Admin pages use `AdminLayout` selected in `resources/js/app.ts`, `<Head>`, the existing `defineOptions` breadcrumbs pattern, `Heading` where appropriate, and existing components in `@/components/ui/`. Settings pages receive the nested `AdminSettingsLayout`. Check `AdminSidebar.vue` and `AdminSettingsLayout.vue` for permission-gated navigation.
- Reuse the existing table, button, badge, input, label, select/combobox, switch and dropdown components. Match the comparable module's spacing, responsive layout, empty/loading states and visible labels. Use typed props and module-specific row types; avoid `any` where the type is known.
- **Drawer sizing & layout standard**: The shared `@/components/ui/drawer/DrawerContent.vue` is a bottom sheet with `max-h-[92vh]`, a handle, overlay and close button. Always size admin form/view drawers across desktop viewports using `class="max-h-[92vh] overflow-y-auto md:inset-x-auto md:right-2 md:left-64"`. **NEVER** add `bottom-2`, `mx-auto`, or arbitrary conflicting `max-w-*` on `DrawerContent`: doing so detaches the fixed bottom sheet from the viewport edge and breaks it into an awkward floating box. Drawer headers must include an icon badge inside `flex size-10 shrink-0 items-center justify-center rounded-xl bg-primary/10 text-primary ring-1 ring-primary/20`, a concise `DrawerTitle`, and `DrawerDescription`. Long forms and detail views must be structured into grouped cards with `space-y-4` or `space-y-5`, responsive grids for metadata pills, and an action footer.
- **Table Actions column standard**: The Actions column in admin tables must consistently use the `DropdownMenu` pattern rather than raw side-by-side text buttons. Use `<TableHead class="w-12 pr-5 text-right"><span class="sr-only">Actions</span></TableHead>` and `<TableCell class="pr-5 text-right align-top" @click.stop>` with a ghost icon trigger `<Button variant="ghost" size="icon-sm" aria-label="Open actions"><MoreHorizontal class="size-4" /></Button>`. Dropdown items must feature Lucide icons (`size-4`), distinct labels, and destructive variants (`variant="destructive" class="text-destructive focus:text-destructive"`) separated by `<DropdownMenuSeparator />`.
- **Table text wrapping & anti-overlap**: `@/components/ui/table/TableCell.vue` applies `whitespace-nowrap` by default. When table cells or expanded sub-rows display user-generated text (titles, names, addresses, notes, or descriptions), you must add `whitespace-normal` to the `<TableCell>` and `block w-full line-clamp-2 break-words` to inner text/button elements. Inside CSS grid sub-rows or drawers, always specify `min-w-0` and `break-words` on column containers so text never overflows horizontally or stacks on top of neighboring columns.
- Confirm destructive actions with `AlertDialog`; compare the `sm:max-w-md` dialogs in Categories, Users, Roles and Finance. Include a clear record name and consequence, cancel/destructive buttons, processing state, and disable duplicate submissions. Enforce deletion and protected-record rules on the server too.
- `AdminLayout.vue` already mounts the Sonner `Toaster`; `resources/js/lib/flashToast.ts` handles shared server success/error flash messages and Inertia flash events. Follow an existing module's notification flow; avoid mounting another toaster or emitting a duplicate success toast. Use `InputError` for validation and existing inline alerts for contextual warnings.
- Use `@inertiajs/vue3` forms/router, `@lucide/vue`, and generated Wayfinder routes/actions. Inspect the generated exports; do not hand-edit generated files. Match the current module's controlled drawer props/events and reset validation errors and form state correctly on reopen.
- For searchable/paginated lists, use a suitable existing server-side filter and `watchDebounced` pattern, preserve query/filter state, render actual pagination links with `decodePaginationLabel`, and verify navigation and empty results. Roles is a deliberately different local-list example; select pagination by data size. Do not ship a template that only displays pagination totals.

## Backend, authorization and audit

1. Use existing admin route groups in `routes/admin.php`: the group already applies the configured admin prefix, `admin.` route-name prefix, admin auth and active-admin middleware. Follow Categories' `Route::apiResource(...)->except(['show'])->names('<slug>')` for drawer CRUD; use resource create/edit routes only if the UI needs pages. Do not duplicate the `admin.` name prefix. Inspect route names with `php artisan route:list --no-interaction` and regenerate Wayfinder as needed.
2. Scaffold applicable PHP files with Artisan `make:*` commands and `--no-interaction`. Follow sibling models, migrations, requests, resources and tests. Include factories, seeders, resources, migrations, indexes or soft deletes only when the module needs them; do not invent domain fields or change dependencies. Use a resource or explicitly selected properties to avoid exposing unintended model data.
3. Add necessary permissions in `database/seeders/RoleAndPermissionSeeder.php`, with the `admin` guard and appropriate group. Follow the existing permission names and never grant a non-system role new access automatically without a product requirement. Authorize every read and mutation on the server; reflect the same permission in navigation, buttons, switches and direct actions. For admin/role delegation preserve the escalation and protected-account checks in existing requests, `Admin::canDelegateRole` and related controllers.
4. Follow neighboring Form Requests for validation and permission checks, and `AuditLogService` for meaningful create/update/delete audit entries. Capture safe before values, avoid secrets, and preserve model-specific protected-record rules. Use server flash messages as existing controllers do. Do not assume every business failure is a successful mutation just because a redirect occurred.
5. Run migrations, permission seeding or browser CRUD only when appropriate for the target environment and user authorization. Avoid destructive or unsolicited external actions; do not modify existing system roles or accounts to test. Changes to dependencies require approval under project rules.

## Verification

- Add meaningful Pest coverage for authorized and forbidden access, create/update/delete, validation, protected records and relevant audit/side effects. Use factories when appropriate. Scaffold tests with Artisan; run the narrow affected suite and project-required formatter and checks. Follow `AGENTS.md` for the full-suite instruction.
- Generate Wayfinder types if routes change; run the appropriate frontend type/build checks. Exercise the actual UI in Chrome when available: create/edit/delete using uniquely marked disposable data, search, filters, pagination, empty/validation states, permissions, drawer scrolling on mobile/desktop, modal cancel/confirm, and one success/error notification. Clean up only records created for this test and report any untested flows accurately.
- Do not invoke `admin-module-tester` automatically: its GitHub issue creation is an external side effect. Use it only when requested or when its workflow and side effects are explicitly authorized.
